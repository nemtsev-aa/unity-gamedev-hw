# Мини-игра [StepByStepButler]

## Особенности реализации:

- Архитектура приложения реализована с помощью паттерна **EventBus**.
- Процесс внедрения зависимостей реализован с помощью **Zenject**.
- Взаимодействие классов и систем реализовано с помощью реактивного программирования (библиотека **R3**). 
- Асинхронные операции реализованы c помощью **UniTask**.
- Анимации реализованы c помощью **DoTween**.

## Основные системы:

- **EventBus** - шина событий, осуществляющая подписки/отписки и запуск событий *IEvent*. События реализованы в виде структур.
- **GameCycle** - реализовывает состояния игрового цикла: старта, паузы, презапуска/возобновления и завершения игры. Классы реализуют интерфейсы (*IGameStartListener*, *IGamePauseListener*, *IGameFinishListener* и др.) благодаря чему соответствующим образом реагируют на изменение состояния игрового цикла.
- **Entity** - сущность, составляющая основу героя. Данная сущность содержит словарь компонентов, которые реализуют различные свойства и параметры героя. Компонент — структура данных (как в ECS), например *HealthComponent* - здоровье героя, *HeroTypeComponent* - тип героя и т.д.
- **IGameSystem** - интерсфейс, позволяющий реализовать необходимые для геймплея системы. *TurnSystem* - система отвечающая за переключение ходов между игроками, *CombatSystem* - система, реализующая механики контр-атак и уникальных способностей героев, *DamageSystem* - система определяющая размер входящего урона героям, *DeathAnimationSystem* - система отображения процесса смерти героя, *ViewSystem* - система визуальных эффектов хода, обновления статуса героев.
- **UISystem** - комплексное решение для отображения пользовательского интерфейса. Включает в себя *UIManager* - менеджер UI-элементов, *ScreenFactory* - фабрику пользовательских окон, *ScreenSwitcher* - диспетчер окон, *UIService* - сервис визуализации героев, *ActiveEffectViewSystem* - система отображения активных эффектов, *DamagePopupSystem* - система отображения входящего урона/лечения.
